## 2. 反例论证（核心）：六项"知道而不用"

每项四要素：是什么 / 为什么不进本项目（指回证据）/ 何种条件翻转 / 红线冲突点。

### 2.1 Parquet（列式存储）

- **是什么**：列式二进制表格格式，为 GB 级分析型扫描（pandas/Spark 列聚合、谓词下推）设计。
- **为什么不用**：全部图谱/评测数据 <1MB（graph_entities.json 73KB）；JSON 人类可读、可 git diff、可逐字节比对——**确定性红线（重建逐字节一致）恰恰依赖文本格式的可比对性**，列式二进制反而牺牲可审计性。列存在此量级收益为零。
- **翻转条件**：语料扩到多部作品/GB 级，且出现跨 run 的列式聚合分析需求。
- **红线冲突**：无直接冲突，纯属无收益。

### 2.2 RDF 三元组栈（W3C 语义网）

- **是什么**：URI 全局标识 + 本体（OWL）+ SPARQL 查询的标准化知识表示，面向**跨数据集开放世界**的链接与推理。
- **为什么不用**：本项目是封闭世界单语料问答，消费者是 Python 进程内的 dict/检索臂。**三元组的思想实际在用**——`graph_events.json` 的 edges 就是 `头-(关系类型)->尾`——但 RDF 的序列化/本体/查询引擎整层机器在单语料场景没有对应收益，只增加依赖与心智负担。
- **翻转条件**：多部 galgame 语料互联、需要跨作品实体对齐（如"篝"与另一作品的同名角色区分）时，URI 标识才有意义。
- **红线冲突**：一条命令复现（新增查询引擎依赖）。

### 2.3 Neo4j / 图数据库

- **是什么**：带 Cypher 查询语言与事务的图数据库，为多用户服务、亿级边、复杂多跳查询设计。
- **为什么不用**：483 节点几千条边，加载成邻接 dict 毫秒级完成全部查询（1 跳 = 一次字典取值）。引入 DB = 新部署依赖 + 服务进程，直接破坏"一条命令复现"与 zip 纪律。框架 §6.3b 在设计期就明令禁止。
- **翻转条件**：图规模 ≥10^6 边、或多用户在线服务、或查询模式需要 3+ 跳变长路径（Cypher 的优化器此时才有价值）。
- **红线冲突**：一条命令复现（红线①）、zip 纪律（服务不可打包）。

### 2.4 Leiden 社区检测（含微软 GraphRAG 全家桶定位）

- **是什么**：社区检测算法（Louvain 改进，保证社区连通）；MS GraphRAG 用它切分图 → LLM 给每社区写摘要 → global search（map-reduce 遍历社区摘要回答全文型问题）。
- **为什么不用**：①**工作负载不匹配**——评测集五类题（局部事实/是否/时序/聚合/不可回答）没有"全文摘要型"提问，社区摘要服务的问题不存在；"整体剧情"类若要做，层次摘要（RAPTOR-lite，方案 d）是更直接且可评测的路径。②**评测锚点不匹配**——本项目金标锚在 chunk 级 rfid（引用校验/Recall@k 同口径），图谱必须能映射回 chunk；事件卡片天然带 chunk_id 锚，社区摘要没有。③**确定性**——Leiden 有随机性（需控 seed），与重建逐字节一致的验收口径相抵。框架 §6.2 对 GraphRAG 的定位（"了解即可，不建议照搬"）即基于此。
- **翻转条件**：语料扩到长篇多线、评测加入"跨全线综述"型问题。
- **红线冲突**：确定性（随机性）；成本（逐社区 LLM 摘要是又一笔建图开销）。

### 2.5 图嵌入（node2vec / TransE / GNN）

- **是什么**：把图结构学习成节点向量，用于**节点相似度**与**链接预测**。
- **为什么不用**：本项目要的是 **chunk 召回**，不是节点相似——实体/参与者/时序结构直接以集合与邻接表消费是**无损**的，经过向量化反而有损（483 节点训嵌入：新增模型 + 训练方差 + 调参，且没有任何一个"只有它能解决的失败模式"）；语义相似这个职责 bge 稠密臂已在担（semantic_gap 层 R@3 0.068→0.386 的增益来自 bge，与图结构无关）。
- **翻转条件**：需要"与该事件结构最相似的事件"这类节点相似服务，或链接预测（补全缺失的时序边）。
- **红线冲突**：确定性（训练随机性）、复现（新增模型工件）。

### 2.6 图遍历（命名澄清：不是不用，是深度限 1）

- **是什么**：BFS/DFS/随机游走等图搜索。
- **实际情况**：**计划里一直在用，只是没叫这个名字**——T11 扩展路的"seed 命中 → 1 跳邻居"就是深度限 1 的 BFS。`hop=1` 是刻意上限而非疏忽：多跳遍历会话题漂移（2 跳后邻居与问题相关性急剧衰减）且证据预算爆炸（top-k 位置被无关块挤占）；时序题"沿时间线定位"也是 rfid 序上的有界遍历。**写报告时应明确这个命名映射**，避免评审误以为图遍历缺位。
