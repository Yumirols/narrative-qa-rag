## 4. 512 截尾影响评估（T4 §8.3-1 正式收口）

工具：`src/analyze_truncation.py`（新增，确定性、零 LLM 调用），输出挂
`runs/20261025-154043/truncation_analysis.json`。方法：lines.jsonl 逐行重建 chunk 正文
（台词行加【说话人】、旁白不加）——**重建一致 483/483、逐行分词可加性 483/483 双验证**；
由此定位每题 gold 证据行在 chunk 内的 token 偏移，与 510（=512−[CLS]−[SEP]）比较。
截尾判定用 base 臂 tokenizer（与 run 日志 n_truncated=187 同源）。

**三级口径（防止单一数字被误读）：**

| 口径 | 数字 |
| --- | --- |
| 块级暴露（chunk 被截） | 187/483 = **38.7%**（超出 token 均值 53、最大 271） |
| 题级 gold 暴露（≥1 gold chunk 被截） | 56/72 = **77.8%**；gold 实例 86/174 = 49.4% |
| 证据丢失（gold 证据行完整落入截尾） | **仅 5/72 = 6.9%**（Q04/Q41/Q49/Q51/Q89） |

**分组对照**（A=gold 未截 n=16 / B=gold 被截证据存活 n=51 / C=证据全落截尾 n=5；
mean R@3/MRR，evaluate.py 口径）：

| 臂 | A | B | C |
| --- | --- | --- | --- |
| bm25_jieba | 0.385 / 0.547 | 0.330 / 0.482 | 0.267 / 0.450 |
| bm25_bigram | 0.635 / 0.625 | 0.363 / 0.518 | 0.267 / 0.462 |
| w2v_avg | 0.083 / 0.168 | 0.157 / 0.204 | 0.100 / 0.240 |
| bge_small | **0.573 / 0.600** | 0.276 / 0.400 | 0.233 / 0.467 |
| bge_base | 0.427 / 0.496 | 0.353 / 0.504 | 0.367 / 0.650 |

层内 A/B 对照（排除层构成混杂，R@3）：literal 6 题 A 组 small 0.667→B 组 11 题 0.409
（jieba 0.750→0.909）；semantic_gap small 1.000（n=3）→0.294（n=17）；structural
0.310→0.185——**gold 被截的题上 bge 显著失分而 BM25 几乎不动**（BM25 全文入索引、
无 512 限制），模式在三层内一致。

**表述红线**：截尾 flag 与 chunk 长度完全共线，A/B/C 组间差是"截尾删证据"与
"长文均值池化稀释"的**联合效应**，不可归因单一机制（demo 案例：路易斯国籍题 gold
579 字排第 4 即稀释的独立证据）。C 组 5 题后果混合（Q49 五臂全脱靶；Q51 仅 bge_base
首位救回；Q41 bge 只得 1/2 gold——恰好丢靠后的那个）。切分不迁就模型（计划坑 5
原则），本评估即处置终态。
