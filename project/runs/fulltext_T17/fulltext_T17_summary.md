## 6. 结论（"为什么要 RAG"的实测回答，如实口径）

1. **质量**：全文臂合并 0.7361 ≤ RAG 关 0.8056——但失分主因是结构性（证据不在该半时正确拒答被判错 + 半 A 过度拒答），gold 在本半时其 yesno 能力（0.9333）反超 RAG（0.6111）。**RAG 的价值不在单题阅读力，而在把 70K token 的输入压到 3.3K 的同时保住 0.80+ 的质量**。
2. **成本**：输入 token 21.5×/题；无前缀缓存时的成本 20×/题。实付仅 ~1.8× 完全依赖"同半 36 题逐字节共享前缀"的布局 + DeepSeek 自动前缀缓存——**换任何不带该机制的端点，全文方案的单题成本立即回到 20 倍**；且 54 道生成题与 judge 复评在全文口径下输入更大、不可扩展，RAG 是唯一可跑全量 90 题 × 评测的方案。
3. **延迟**：实测打平（≈1.4s P50 两方法），阶段计划 H5 的"≥5×"预期被证伪——原因即前缀缓存折价 TTFT，冷启动首调也仅 2.1s。
4. **协议健壮性外溢**：JSON 协议 + rfid 标注行 + 两规则校验在 70K token 上下文里零解析失败、零编造 rfid、拒答正确率 1.0——生成协议本身对上下文长度不敏感。
5. **位置消融**：未见 lost-in-the-middle 形态（9/10 稳定），原理点④素材以"未复现+单例反向翻转（Q52）"如实入报告。
